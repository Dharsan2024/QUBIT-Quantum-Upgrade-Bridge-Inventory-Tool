Abstract

Migrating the world's deployed cryptography to post-quantum (PQC) standards is a decade-scale undertaking, made urgent by the Harvest-Now-Decrypt-Later (HNDL) threat: an adversary records encrypted data today and decrypts it once a Cryptographically-Relevant Quantum Computer (CRQC) exists. Existing tools address fragments — discovery, or a Cryptographic Bill of Materials (CBOM), or code transformation — but none connects discovery → risk quantification → automated, verified remediation → runtime proof.

We present QUBIT, an offline, open-source platform that unifies this pipeline. It (1) discovers cryptographic assets and the broader HNDL exposure surface — hardcoded secrets, keys, tokens, PII — via AST- and pattern-based scanning; (2) quantifies each asset's HNDL risk by fusing a Monte-Carlo simulation of CRQC arrival with a data-shelf-life model, under Mosca's inequality; (3) generates and safety-validates patches to NIST PQC algorithms (ML-KEM, ML-DSA) with a local LLM plus deterministic template fallbacks, in a sandbox where a failing patch can never merge; and (4) proves the migration on the wire via a hybrid classical+PQC TLS terminator (X25519MLKEM768). The contribution is the synthesis: a continuous, calibrated HNDL score over a programmatically-discovered inventory, wired to a verification-gated remediation loop and an on-wire proof, packaged to run offline on a laptop.

1 Introduction

1.1 Motivation

NIST finalized the first PQC standards (FIPS 203 ML-KEM, FIPS 204 ML-DSA, FIPS 205 SLH-DSA) in 2024, and standards bodies now advise beginning migration immediately. The urgency is not that a CRQC exists today — it does not — but the HNDL model: data with a long secrecy shelf-life (health, financial, state, long-lived credentials), encrypted today with quantum-vulnerable algorithms, can be harvested now and decrypted later. What to migrate first is therefore a risk-prioritization problem governed by Mosca's inequality: if X (shelf-life) + Y (migration time) > Z (time to a CRQC), the data is already effectively compromised.

1.2 The gap

Discovery tools find algorithm usages but do not quantify risk. CBOM generators produce compliance artifacts but do not remediate. Code-transformation research demonstrates LLM rewriting without a safety gate or runtime proof. No open system connects all four stages into one calibrated, reproducible loop — and none frames the problem around the full HNDL exposure surface rather than crypto algorithms alone.

1.3 Contributions

  1. A unified offline pipeline — discovery → HNDL risk → verified remediation → on-wire proof — in one reproducible artifact.
  2. An HNDL exposure-surface model broadening discovery to the secrets, keys, tokens, and PII an HNDL adversary harvests, each with an exploit narrative. measured
  3. A fused, calibrated HNDL score: Monte-Carlo CRQC-arrival simulation + Bayesian/closed-form exposure model + XGBoost regressor with split-conformal confidence intervals. modeled
  4. A safety-gated migration loop: local-LLM + template patches validated in a sandbox so an unsafe patch cannot be accepted. measured
  5. A runtime proof: a hybrid TLS terminator negotiating X25519MLKEM768, verified by handshake capture. measured

2 Threat Model & Background

Adversary. A passive HNDL adversary that records ciphertext or exfiltrates encrypted data today, and gains a CRQC at future time Z. Shor's algorithm breaks RSA/ECC once a sufficient CRQC exists; Grover halves symmetric security (mitigated by doubling key sizes). QUBIT does not model active attackers or side-channels.

Mosca's inequality. Per asset, QUBIT estimates the Mosca margin Z − (X + Y) in years; a negative margin means the data's secrecy requirement outlives its crypto — already HNDL-compromised. This margin is the backbone of prioritization.

CRQC arrival is modeled, not measured. modeled No CRQC exists, so Z cannot be observed. QUBIT models it as a distribution via Monte-Carlo over published hardware resource estimates (Webber et al.; Gidney & Ekerå), blended with an expert-survey log-normal CDF. This is the correct scientific treatment of an unrealized event and is labeled a simulation throughout.

4 Discovery: the HNDL Exposure Surface

4.1 Cryptographic discovery

The code scanner parses source with tree-sitter and matches a YAML rule catalog (Python, Java, Go) against the AST, normalizing each finding against a canonical algorithm registry (name, family, key size, quantum verdict, PQC replacement). Config files, certificates/keys, and live TLS endpoints (active enumeration with PQC-group probing) have dedicated scanners. Each asset carries redacted evidence (±5 lines + file:line) and a stable cross-scan fingerprint so trends and remediation deltas are queryable.

4.2 Broadening to the exposure surface measured (contribution)

A crypto-only view understates HNDL risk: the threat is everything weak crypto protects. QUBIT adds a high-precision secret/PII detection pass over source and config:

  • Secrets: AWS / GitHub / Slack / Google / Stripe keys, JSON Web Tokens, PEM private-key blocks, hardcoded passwords.
  • Sensitive data (PII): email addresses, credit-card numbers, US SSNs.

Placeholders and example values are filtered to keep precision high. Each finding uses the additive secret / sensitive-data type and carries a per-finding HNDL exploit narrative — what the adversary harvests now and how it is exploited once a CRQC arrives. Verified end-to-end through the desktop app; five dedicated tests.

4.3 Output artifact

The database is the source of truth; the exportable compliance artifact is a CycloneDX 1.7 CBOM validated against the ECMA-424 schema.

5 Risk Quantification modeled

QUBIT computes a per-asset HNDL risk in [0,1] with a calibrated confidence interval:

  1. CRQC-arrival timeline (Z). A Monte-Carlo simulation (default 10k+ trials) over a surface-code resource model, producing P(CRQC ≤ year), optionally blended with an expert-survey log-normal CDF via a Bradley-Terry-adjacent consensus. Anchor-tested against Webber/Gidney figures.
  2. Data exposure (X). A closed-form P_HNDL integral (Gauss-Legendre) that agrees with an independent 5-node Bayesian network (pgmpy) to within <0.02 — a cross-validation of the two formulations.
  3. Mosca margin. Z_median − (X_shelf_life + Y_migration); negative ⇒ already compromised.
  4. Calibrated score. An XGBoost distillation regressor over a 34-dim frozen feature vector, wrapped in split-conformal prediction for a distribution-free CI, with TreeSHAP attributions surfaced in the UI.
Honest negative result A DistilBERT sensitivity classifier trained on synthetic snippets scored near-perfect held-out accuracy but only ~2.8% agreement on real code (template memorization, not transfer). It is documented as a negative result; the product ships the transparent heuristic classifier instead — a deliberate choice not to over-claim.

6 Automated, Verified Migration

6.1 Ordering

A directed dependency graph over discovered assets (key-generation before use, shared certificates together, library upgrades first) is condensed over strongly-connected components into atomic migration units and topologically ordered; work is scheduled by risk ÷ effort (WSJF) within the ready frontier.

6.2 Generation & the safety gate measured (contribution)

Patches come from a local LLM (Ollama, qwen2.5-coder) via structured-output edits — QUBIT computes the unified diff itself, never trusting LLM line numbers — or from deterministic libcst/template transforms needing no GPU. Every candidate passes a sandboxed pipeline (apply → parse → compile → re-scan) in a network-disabled container; a patch that fails any stage cannot be accepted, and human approval is mandatory. Safety is the claim, independent of LLM success rate. Verified live: an RSA-2048 → ML-KEM-768 hybrid patch was LLM-generated and passed parse/compile/re-scan, reaching proposed.

6.3 Runtime proof measured

qubit-bridge stands up a hybrid TLS terminator on the same port a classical service used; qubit bridge verify confirms the negotiated group is X25519MLKEM768 (TLS 1.3). Verified: verify --expect X25519MLKEM768 returns PASS against the live hybrid nginx.

8 Limitations & Threats to Validity

  1. The evaluation gap (§7) — comparative P/R/F1, calibration, and pass@k are not yet measured. Present them as planned, not achieved.
  2. The CRQC timeline is a model — all Z-derived numbers are simulation outputs conditioned on published estimates, not forecasts.
  3. Detection recall is bounded by the rule catalog and regex patterns; the secret/PII pass trades recall for precision and misses obfuscated secrets.
  4. LLM patch success is variable and hardware-dependent; the honest claim is safety (the gate), not a headline success rate.
  5. Single-machine scope — dev-grade token auth; multi-tenant hardening, packaging, and observability are future work.

9 Conclusion

QUBIT shows the fragmented PQC-migration toolchain can be unified into one offline, reproducible loop a practitioner runs on a laptop: discover the full HNDL exposure surface, quantify risk with a calibrated CRQC-arrival model under Mosca's inequality, generate and safety-validate PQC patches, and prove the migration on the wire. The synthesis — not any single stage — is the contribution. The clear next step is the external-baseline evaluation (E1–E4) that converts demonstrated functionality into comparative empirical evidence.

Reproducibility — one-command demo: uv run qubit run <path|git-url> (scan → risk → migrate) or qubit demo run --all (adds the hybrid-bridge loop). Gate: uv run ruff check <pkg> && uv run mypy <pkg>/src && uv run pytest <pkg> -q. Full specification in docs/design/00–08.
